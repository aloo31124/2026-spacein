deepseek 方案多
------------------------------------------------

要避免在 `map` 中產生 `null` 值，可以使用 `filter` 先過濾掉不符合條件的項目，
再進行 `map` 轉換。以下是修正後的程式碼：

### 修正方案（使用 filter + map）
    ```javascript
    return historyList
    .map(history => {
        const user = userList.find(user => user.id === history.userId);
        const payment = paymentList.find(payment => payment.id === history.paymentId);
        return { user, payment, history }; // 暫時包裝起來
    })
    .filter(({ user, payment }) => user && payment) // 過濾掉無效資料
    .map(({ user, payment, history }) => ({ // 正式轉換
        email: user.email,
        planName: payment.planName,
        ...history
    }));
    ```

### 替代方案（使用 reduce）
    ```javascript
    return historyList.reduce((result, history) => {
    const user = userList.find(user => user.id === history.userId);
    const payment = paymentList.find(payment => payment.id === history.paymentId);
    
    if (user && payment) {
        result.push({
        email: user.email,
        planName: payment.planName,
        ...history
        });
    }
    
    return result;
    }, []);
    ```

### 最佳實踐（函數式組合）
    ```javascript
    const joinHistoryData = (history) => {
    const user = userList.find(u => u.id === history.userId);
    const payment = paymentList.find(p => p.id === history.paymentId);
    return user && payment ? { 
        email: user.email, 
        planName: payment.planName,
        ...history 
    } : null;
    };

    return historyList
    .map(joinHistoryData)
    .filter(Boolean); // 自動過濾掉 null/undefined
    ```

### 主要改進點：
1. **避免 null 值**：使用 filter 或 reduce 確保結果陣列不含無效項目
2. **程式碼更清晰**：將查找邏輯與轉換邏輯分離
3. **效能考量**：reduce 方案在大型陣列中效能較好
4. **可讀性**：函數式組合讓意圖更明確

### 注意事項：
- 原始程式中的 `user ? user.email : "無 email"` 已移除，因為經過過濾後 user/payment 必定存在
- 若需要保留預設值，可在最後的 map 中重新加上
